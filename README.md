# ASTRA Trade Bot

ASTRA is a fail-closed trading platform focused on durable market truth, deterministic risk admission, idempotent OMS behavior, exact execution/accounting evidence, reconciliation, recovery and explicit operational authority.

The repository deliberately separates **engineering qualification** from **strategy promotion** and from **trading authority**. Passing CI is evidence that covered software contracts hold; it is never permission to route orders or a profitability claim.

## Source of truth

Current status is no longer maintained as free-form prose.

- `CURRENT_SYSTEM_STATUS.json` is the generated machine-readable status surface.
- `qualification/engineering/*.json` contains immutable engineering qualification evidence for specific subject SHAs.
- `qualification/strategy/*.json` contains strategy evidence or evidence pointers and cannot be promoted by engineering CI.
- `RELEASE_IDENTITY_V109.json` and `LIVE_EXECUTION_STATUS_V109.json` retain the immutable historical release/authority boundary.
- `tools/system_status.py` compiles and validates these sources.

Use:

```bash
python tools/system_status.py --check
python tools/system_status.py --show
```

`--check` fails when committed status artifacts drift from their sources. `--show` resolves the exact checkout SHA at runtime and reports whether the checkout is the latest engineering-qualified subject, a descendant changed since that qualification, or a divergent history.

Maintainers may run `python tools/system_status.py --write` after adding or changing an explicit source manifest. Generated status must not be edited by hand.

## Core architecture

The intended operational flow is:

```text
Bybit public market data
  -> finalized durable market bars
  -> continuity / overlap repair
  -> fenced operational decision worker
  -> strategy target
  -> executable order normalization
  -> factual portfolio / market / account snapshot
  -> pre-trade risk admission
  -> pending exposure reservation
  -> OMS / outbox
  -> ARM / HALT final dispatch interlock
  -> broker private execution
  -> immutable execution facts
  -> accounting projection
  -> portfolio
  -> broker / financial-activity reconciliation
  -> authoritative runtime readiness
```

The system is designed around one ordering principle: **external exchange facts outrank internal assumed state**.

## Safety invariants

ASTRA is expected to fail closed whenever required operational truth is missing, stale, conflicted or ambiguous. Important invariants include:

- no risk-increasing mutation without current risk authorization;
- no duplicate submit/cancel/replace authority across concurrent workers;
- no strategy decision from stale, gapped, conflicted or non-final market data;
- no decision completion after the exact evidence window has been invalidated;
- no new BUY exposure while portfolio, financial-activity or execution/accounting truth is unresolved;
- no fabricated execution economics when the broker has not supplied exact facts;
- no automatic conversion of a green test run into Demo, mainnet or live authority.

## Engineering qualification versus trading qualification

Engineering manifests describe the exact software subject and the CI evidence observed for it. They may enumerate implemented capabilities, but their promotion fields are required to remain fail-closed.

Strategy qualification is a separate evidence plane. The latest frozen Bybit price-only evidence preserved by this repository remains negative and therefore does not establish a positive trading edge. See `qualification/strategy/bybit_price_only_frozen_negative.json`.

Trading authority is a third plane. `LIVE_EXECUTION_STATUS_V109.json` remains `SOURCE_AND_CI_QUALIFICATION_ONLY`; external order routing and live trading are false. Demo/mainnet authority likewise remains false until separate explicit promotion evidence exists.

## Development discipline

Changes that affect trading correctness should follow this sequence:

```text
bounded issue / invariant
  -> branch
  -> implementation
  -> negative and concurrency acceptance tests
  -> exact-head CI
  -> compare against current main
  -> guarded merge
  -> post-merge qualification
```

Do not treat stale green runs, historical documentation or a different SHA as proof for the current code.
